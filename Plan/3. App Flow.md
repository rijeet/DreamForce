# App Flow: Dream Force

## Pages

1. **Create account** — required Privacy Policy and Terms acknowledgement, optional versioned screen-time sync consent, and Google sign-in.
2. **First-run profile setup** — display name, timezone, and optional personal details.
3. **Today** — date, quick-start activities, today’s plan, and daily review entry point.
4. **Choose activity** — search, quick picks, recent activities, and create-custom action.
5. **Create activity** — activity name, icon, total duration, automatic focus/rest preview, and save.
6. **Focus timer** — active focus/rest phase, countdown, pause, skip, and finish controls.
7. **Session complete** — actual session summary and next actions.
8. **Weekly plan** — selected-day schedule, day selector, start/skip actions, and add activity.
9. **Edit weekly plan** — edit, reorder, add, and copy planned activities.
10. **Daily review** — mood, reflection, optional reason tags, and save.
11. **Insights: Activity** — period selector, category chart, yearly comparison heatmap, selected-day details, and KPIs.
12. **Insights: Screen time** — Android-only app-time chart, yearly comparison heatmap, selected-day details, and per-app list.
13. **Usage access explanation** — Android-only explanation, Settings handoff, and decline path.
14. **Profile and settings** — preferences, account, appearance, notifications, privacy, terms, and help.
15. **Edit profile** — display name, avatar, optional gender/date of birth/location/profession, and timezone.
16. **Privacy Policy** — read-only legal content.
17. **Terms and Conditions** — read-only legal content.
18. **Account export / deletion flows** — protected account-management actions with confirmation.
19. **Admin CRM dashboard** — role-gated aggregate monitoring, support-ticket resolution, global templates, and notification campaigns.

## Navigation model

The persistent bottom navigation contains four destinations:

| Destination | Default page | Availability |
| --- | --- | --- |
| Today | Today | Android and iOS |
| Plan | Weekly plan | Android and iOS |
| Insights | Activity insights | Android and iOS; Screen time is Android-only |
| Profile | Profile and settings | Android and iOS |

The centered floating **+** action opens **Choose activity** from any primary destination. It is not a separate bottom-navigation destination. While an active session exists, a compact session return control is displayed above navigation where space allows.

## User journeys

### 1. Create account and first setup

1. User opens Dream Force and lands on **Create account**.
2. User opens **Privacy Policy** or **Terms and Conditions** if they want to read them.
3. User checks the agreement box and taps **Continue with Google**.
4. Google authentication succeeds and the app creates or retrieves the Dream Force account.
5. User lands on **First-run profile setup**, sets display name and timezone, and saves.
6. User lands on **Today**.

### 2. Start a saved activity

1. User lands on **Today**.
2. User taps a Quick start activity card, or taps the floating **+** button.
3. The quick-start action opens its start preview; the floating **+** opens **Choose activity**.
4. User chooses a saved activity and confirms the total duration.
5. App generates the automatic focus/rest schedule and starts **Focus timer**.
6. User pauses or resumes the session; the primary timer button changes label to match the current state.
7. When the final automatic phase ends, app opens **Session complete** and saves the session locally; it syncs when available.
8. If the user taps **Delete session**, app asks for confirmation and records the active session as cancelled while retaining elapsed time in private history.
9. User taps **Done** to return to **Today**, or **Start another activity** to open **Choose activity**.

### 3. Create a reusable activity

1. User taps floating **+** from a primary screen.
2. App opens **Choose activity**.
3. User taps **Create custom activity**.
4. App opens **Create activity**.
5. User enters a name, chooses an icon, and changes total duration.
6. App immediately shows the calculated focus/rest plan; the user cannot edit phase values.
7. User taps **Save activity**.
8. App saves the template and returns to **Choose activity** with the new activity available.

### 4. Manage the weekly plan

1. User taps **Plan** in bottom navigation.
2. App opens **Weekly plan** on the current local day.
3. User taps a weekday to view that day’s planned activities.
4. User taps **Add activity** to open **Choose activity**, chooses a saved activity, then sets an optional local start time.
5. User taps **Edit** to open **Edit weekly plan**.
6. User edits an entry, reorders it, copies the day, or adds an entry.
7. User taps **Done**; app validates and saves future plan occurrences without rewriting completed history.

### 5. Complete a daily review

1. User taps **Review today** from **Today**.
2. App opens **Daily review** for the user’s local calendar date.
3. User optionally selects mood/reason tags and writes a reflection.
4. User taps **Save review**.
5. App saves locally and returns to **Today** with an “Edit review” state.

### 6. Review Activity insights

1. User taps **Insights**.
2. App opens **Insights: Activity**.
3. User taps Day, Week, Month, or Year to change the total, donut chart, and category list.
4. User selects a heatmap year or quarter shortcut, or scrolls the heatmap horizontally.
5. User taps a heatmap day.
6. The selected-day card updates with Dream Force focus activity and screen-time comparison.

### 7. Enable Android screen-time insights

1. Android user opens **Insights** and taps **Screen time**.
2. User may enable account sync after reviewing the fields and purpose: daily app names/identifiers, usage totals, local dates, and timezone. Declining keeps the screen-time view on-device only.
3. If Usage Access is unavailable, app explains the Android permission and opens Settings only after the user taps **Set up Usage Access**.
4. User grants or declines Usage Access in Android Settings and returns to Dream Force; the app re-checks the permission.
5. When both sync consent and Usage Access are enabled, app reads Android daily aggregates, uploads them to the authenticated user's private account, and displays the account summary.
6. Turning off screen-time sync blocks future uploads and deletes that user's uploaded screen-time rows. It does not revoke Android Usage Access or clear the on-device summary.
7. Declining or revoking either choice keeps core Dream Force features available.

### 8. Edit profile and preferences

1. User taps **Profile**.
2. User taps **Edit profile**.
3. User updates display name/avatar and any optional fields.
4. User taps **Save profile**.
5. App validates and saves the profile, returning to **Profile and settings**.
6. From Profile, user may update appearance, time/language, notification preferences, privacy actions, terms, or support options.

### 9. Admin CRM operations

1. A script-provisioned admin signs in with email and password.
2. Role-based authorization opens **Admin CRM dashboard**; standard users cannot route to or query it.
3. Admin switches Overview, Tickets, Templates, and Notify sections and chooses Day, Week, Month, or Year.
4. In Tickets, admin assigns, replies to, resolves, or closes support tickets; internal notes are never shown to users.
5. In Templates, admin creates/publishes global activity templates and weekly-plan templates.
6. In Notify, admin drafts or schedules a notification campaign; the worker delivers only to eligible users with notification permission.
7. Overview shows aggregate focus activity, active users, top performers, and privacy-bounded Top 10 app summaries. Admins cannot open a user’s app timeline, installed-app list, private profile, or daily review.

## Error and empty states

### Authentication

- **Google sign-in cancelled:** Remain on Create account; show a non-blocking “Sign-in was cancelled” message.
- **Provider/network failure:** Remain on Create account; preserve consent checkbox and offer Retry.
- **Agreement not checked:** Disable Google sign-in CTA and explain that the terms and privacy acknowledgement is required.
- **Expired/invalid identity response:** Return to Create account with generic retry guidance; never show raw provider payloads.

### Activities and timer

- **No activities yet:** Choose activity shows starter templates and a prominent Create custom activity action.
- **No search results:** Show “No matching activities found” with Create custom activity.
- **Invalid activity name/duration:** Keep entered values, show inline validation, and prevent save until valid.
- **Timer already active:** Show Return to active session or Finish existing session; never create two running sessions.
- **Delete session:** Require confirmation before cancelling the active session. Keep elapsed focus/rest totals in private history; do not hard-delete audit/session records.
- **App restart / background recovery:** Reconstruct from persisted timestamps and show restored state; flag material clock discrepancies.
- **Notification unavailable/denied:** Continue timer in-app and show a one-time explanation; core timer remains usable.

### Plans and reviews

- **No planned activities:** Weekly plan offers Add activity; Today offers Plan your week and Start an activity.
- **Plan version conflict:** Preserve local draft and offer Reload or Review local edits; never overwrite silently.
- **No review data:** Daily review opens blank and remains valid even with zero completed sessions.
- **Review save failure:** Keep local draft and show “Saved on this device; sync pending” where appropriate.

### Insights and usage access

- **No completed focus sessions:** Activity Insights shows an empty chart/list with Start an activity action.
- **Usage Access denied/revoked:** Do not show app data; show Android-only explanation and Open Settings action.
- **Usage data delayed/incomplete:** Display an updated timestamp and explain that Android provides aggregate estimates.
- **iOS Screen time request:** Do not expose Screen time navigation or permission flow; keep Activity Insights only.
- **No heatmap data for selected year:** Render neutral/unavailable cells, keep year picker, and explain no recorded data exists.

### Network and service

- **Network failure:** Keep cached content visible; allow safe offline work; queue writes in encrypted local outbox.
- **Server error:** Preserve draft/input, show a retry action and request ID in optional technical details.
- **Account deletion pending:** Restrict new writes as required, show deletion status, and provide the documented cancellation/support route if policy permits.
- **CRM access denied:** Return a standard user to Today and return `403` for every CRM API route; do not reveal dashboard metadata.
- **No opted-in app aggregates:** Show “No aggregate app data for this period” in Top 10 Apps; do not substitute an individual user’s usage data.
