# Dream Force Planning Documents

Read these documents in this order before changing product behavior or architecture:

1. `PRODUCT_REQUIREMENTS.md` — product scope and acceptance criteria.
2. `TECHNICAL_REQUIREMENTS.md` — locked architecture, deployment, security, and integration decisions.
3. `Backend Schema.md` — persistent data model, access rules, and serverless data flow.
4. `Session State Machine Specification.md` — authoritative timer/session persistence and transition rules.
5. `UI-UX DesignBrief.md` and `3. App Flow.md` — user interface and navigation behavior.
6. `Implementation Plan.md` — delivery order and validation gates.
7. `Google OAuth and Vercel Setup.md` — local environment, Google OAuth, and deployment setup.
8. `frontend_reference.html` — interactive visual reference; it does not define backend behavior.

The interactive reference is intentionally stored here with the approved design documents.
